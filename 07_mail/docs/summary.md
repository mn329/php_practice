# 07章 メール送信のポイント

参考：`07_php_mail.pdf` / [チェックリスト](https://edu.logicoya.com/checklist_viewer/?category=php_v3&id=07_mail)

## 1. アプリの全体像

```
index.php ──POST──▶ send.php ──▶ Contact.php ──SMTP──▶ smtp.gmail.com ──▶ 相手の受信箱
（フォーム）     （受け取り・チェック）  （PHPMailerで送信）
                     │
           失敗 → index.php に戻る（入力値はセッションに保存してあるので残る）
           成功 → result.php（完了画面。セッションの入力値を消す）
```

| ファイル  | 役割                                                |
| --------- | --------------------------------------------------- |
| `public/` | ブラウザから見える場所（`-t public` で公開）        |
| `src/`    | 公開しないプログラム（Contact.php、メールのひな形） |
| `.env`    | パスワードなどの接続情報（Git に入れない）          |

## 2. メールが届く仕組み

PHP が相手の受信箱にメールを直接入れるわけではありません。**自分のメールサーバー（Gmail）に預けて、配送を頼みます。**

| 区間                 | ポート        | 認証 | 内容                                                                     |
| -------------------- | ------------- | ---- | ------------------------------------------------------------------------ |
| ① 送信（Submission） | **587** / 465 | あり | アプリが自分のサーバーにメールを預ける。**PHPMailer がやるのはここだけ** |
| ② 配送（Relay）      | 25            | なし | サーバーどうしが宛先のサーバーへ届ける                                   |
| ③ 受信               | IMAP / POP3   | —    | 相手がメールを読む                                                       |

- 25番は「誰からでも受け付けるが、自分宛てしか受け取らない」入口です。
- 587番は「認証した人からしか受け付けないが、どこ宛てでも送る」入口です。
- 昔は25番だけで両方を担っていたため、誰でもどこへでも送れる**オープンリレー**ができ、スパムに悪用されました。そこで送信専用の587番が作られました。

## 3. SMTP と TLS

**SMTP** はメールを送るための通信ルールです（受信は POP3 / IMAP）。送るには次の5つの設定が必要です。

| 項目     | このアプリでの値 |
| -------- | ---------------- |
| Host     | smtp.gmail.com   |
| Port     | 587              |
| 暗号化   | tls              |
| Username | Gmail アドレス   |
| Password | アプリパスワード |

SMTP は暗号化されていない文字のやり取りなので、**TLS**（https の s と同じ技術）で暗号化します。方法は2つあり、ポート番号で決まります。

| 観点                         | STARTTLS                         | SMTPS                                    |
| ---------------------------- | -------------------------------- | ---------------------------------------- |
| ポート                       | **587**（今回はこちら）          | 465                                      |
| PHPMailer での指定           | `'tls'`                          | `'ssl'`                                  |
| 暗号化が始まるタイミング     | 平文で接続し、途中から暗号化する | 接続した直後から暗号化する               |
| 仕組みの安全性               | 平文の区間があるぶん弱点がある   | より安全（2018年の標準 RFC 8314 で推奨） |
| PHPMailer で正しく使った場合 | 実用上は十分安全                 | 安全                                     |
| 対応しているサービスの多さ   | ほぼすべて                       | 多いが、すべてではない                   |

👉 **「587 なら tls、465 なら ssl」とセットで覚えます。** 組み合わせを間違えると接続できません。

### STARTTLS の弱点

最初の平文の区間を悪用する攻撃が知られています。SMTPS には平文の区間がないので、これらは成り立ちません。

| 攻撃                    | 内容                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| STARTTLS ストリッピング | 通信の途中にいる攻撃者が「250 STARTTLS が使えます」の行を消し、暗号化しないまま進めさせる |
| コマンドの注入          | 暗号化前に仕込んだコマンドが、暗号化後に実行されてしまう実装上のバグ                      |

### それでも 587 + STARTTLS で問題ない理由

1. **PHPMailer は暗号化できないとき送信を止めます。** `SMTPSecure = 'tls'` を指定していると、STARTTLS が使えなかった場合はエラーになり、平文では送りません。ストリッピングされても失敗するだけで、パスワードは流れません。
2. **平文の区間に重要な情報は流れません。** 暗号化の前に送るのはあいさつ（EHLO）だけで、パスワードと本文は暗号化したあとに送ります。
3. **証明書を確認します。** PHPMailer は標準で、接続先が本物の smtp.gmail.com かを確かめます。

教材が 587 を使うのは、送信用の標準ポートとしてほとんどのサービスが対応していて、Gmail も推奨しているためです。465 は一度「廃止」扱いになり、あとから標準に戻ったという経緯もあります。

どちらを使っても間違いではありません。Gmail は両方に対応しているので、`.env` を次のように変えるだけで SMTPS に切り替えられます。

```ini
MAIL_PORT=465
MAIL_ENCRYPTION=ssl
```

## 4. 送信元の認証（SPF・DKIM・DMARC）

メールの From は誰でも自由に書けるため、なりすましができてしまいます。受信側は、送信元ドメインの DNS に公開された情報で本物かどうかを確かめます。

| 技術  | 確かめること                                                                                 |
| ----- | -------------------------------------------------------------------------------------------- |
| SPF   | 送信元の IP アドレスが、ドメインの持ち主に許可されたものか                                   |
| DKIM  | 電子署名が正しく、途中で改ざんされていないか                                                 |
| DMARC | SPF・DKIM の結果をまとめて判定し、失敗したメールの扱い（none / quarantine / reject）を決める |

Gmail から送る場合は Google 側で設定済みなので、自分で設定する必要はありません。独自ドメインで送るときは、自分で DNS に設定します。

## 5. Gmail のアプリパスワード

- 普段のログインパスワードは使えません。**2段階認証をオンにしてから、16桁のアプリパスワードを発行します。**
- 漏れたときは、そのアプリパスワードだけを削除すれば止められます。

## 6. `.env` と phpdotenv

パスワードをコードに直接書くと、Git に登録した時点で公開されたのと同じになります。そのため接続情報は `.env` に分けます。

```php
use Dotenv\Dotenv;

$dotenv = Dotenv::createImmutable(__DIR__ . '/..'); // src の1つ上（07_mail）の .env を読む
$dotenv->load();                                     // 読み込んだ値が $_ENV で使えるようになる

$this->host = $_ENV['MAIL_HOST'];
$this->port = (int) $_ENV['MAIL_PORT'];              // .env の値は文字列なので整数に変換する
```

- `.env` は `.gitignore` で Git 管理から外します。
- `.env.sample` はダミーの値だけを入れた見本で、こちらは Git で管理します。

## 7. PHPMailer で送る（Contact.php）

PHP 標準の `mail()` は認証も TLS も扱えないため、PHPMailer を使います。

```php
// 設定（setupMailer）
$this->mailer = new PHPMailer(true);   // true にするとエラーが例外になる
$this->mailer->isSMTP();               // SMTP で送る
$this->mailer->SMTPAuth   = true;      // ログインする
$this->mailer->Host       = $this->host;
$this->mailer->SMTPSecure = $this->encryption;  // tls
$this->mailer->Port       = $this->port;        // 587
$this->mailer->CharSet    = 'UTF-8';   // 日本語の文字化けを防ぐ

// 送信（send）
try {
    $this->mailer->setFrom($this->from_address, $this->from_name); // 差出人
    $this->mailer->addAddress($email, $name);                      // 宛先
    $this->mailer->isHTML(true);                                   // HTML メールにする
    $this->mailer->Subject = $this->subject;
    $this->mailer->Body    = $html;
    return $this->mailer->send();       // 成功すると true
} catch (Exception $e) {
    return $this->mailer->ErrorInfo;    // 失敗した理由の文字列
}
```

ポイントは、**成功したら `true`、失敗したら例外を `catch` してエラー文を返す**ことです。send.php ではこの戻り値を `$result === true` で判定しています。

## 8. メール本文のテンプレート

```html
<p><strong>名前:</strong> {{name}}</p>
```

`loadTemplate()` が `str_replace` で `{{name}}` を実際の値に置き換えます。**配列のキーとプレースホルダの名前が1文字でも違うと置き換わらず、`{{name}}` がそのままメールに出ます。** 本文は `nl2br()` で改行を `<br>` に変換しています。

## 9. セッションの使い方（send.php → index.php → result.php）

send.php から index.php へは `header("Location: ./")` で移動します。このとき `$_POST` は引き継がれないので、ページをまたいで値を持ち運ぶ箱としてセッションを使います。

### 保存しているもの

保存しているのは **`name`・`email`・`body`・`error` の4つ**だけです。

| キー                 | 中身                       | 例                                         | 何のために保存するか                       |
| -------------------- | -------------------------- | ------------------------------------------ | ------------------------------------------ |
| `$_SESSION['name']`  | フォームに入力した名前     | `テスト 太郎`                              | エラーで戻ったとき、入力欄に戻すため       |
| `$_SESSION['email']` | フォームに入力したアドレス | `abc`                                      | 同上                                       |
| `$_SESSION['body']`  | フォームに入力した内容     | `テスト送信です。`                         | 同上                                       |
| `$_SESSION['error']` | エラーメッセージ           | `有効なメールアドレスを入力してください。` | フォームに戻ったとき、エラーを表示するため |

### 誰が入れて、誰が使って、誰が消すか

| キー                      | 入れる（send.php）   | 使う（index.php）    | 消す                       |
| ------------------------- | -------------------- | -------------------- | -------------------------- |
| `name` / `email` / `body` | 送信されるたびに必ず | 入力欄の初期値にする | result.php（成功したとき） |
| `error`                   | 失敗したときだけ     | エラー表示に使う     | index.php（表示した直後）  |

### 場面ごとの中身の変化

**A. 入力ミスのとき**（アドレスに `abc` と入れた場合）

| タイミング               | `name` | `email` | `body`     | `error`                 |
| ------------------------ | ------ | ------- | ---------- | ----------------------- |
| send.php で保存          | 太郎   | abc     | こんにちは | （なし）                |
| validate() が NG         | 太郎   | abc     | こんにちは | 有効なメールアドレスを… |
| index.php で表示した直後 | 太郎   | abc     | こんにちは | **消える**              |

画面には「太郎・abc・こんにちは」が入力欄に残り、エラーが1回だけ表示されます。

**B. 送信に成功したとき**

| タイミング                      | `name`     | `email`        | `body`     | `error`  |
| ------------------------------- | ---------- | -------------- | ---------- | -------- |
| send.php で保存                 | 太郎       | taro@gmail.com | こんにちは | （なし） |
| send() 成功 → result.php で削除 | **消える** | **消える**     | **消える** | （なし） |
| 「フォームに戻る」で index.php  | —          | —              | —          | —        |

入力欄は空になります。

### もし保存しなかったら / 消さなかったら

| やらなかったこと                    | 起きること                                                   |
| ----------------------------------- | ------------------------------------------------------------ |
| send.php で `name` などを保存しない | エラーで戻ったとき入力欄が空になり、最初から入力し直しになる |
| index.php で `error` を消さない     | 再読み込みするたびに同じエラーが出続ける                     |
| result.php で `name` などを消さない | 送信成功後にフォームへ戻っても、前回の入力が残っている       |

`header("Location: ...")` のあとには必ず `exit;` を書きます。

## 10. セキュリティの注意

- パスワードは `.env` に書き、Git に入れません。
- 画面に表示する値は `htmlspecialchars()`（`$h()`）でエスケープします。
- 今回はメール本文に埋め込む値もエスケープしました。HTML メールにタグを仕込まれないようにするためです。
- 誰でも使える本番のフォームでは、入力されたアドレスにそのまま送ると迷惑メールの中継に悪用されます。送信回数の制限や CAPTCHA を加えます。

## よくあるエラー

| エラー                 | 原因                                        |
| ---------------------- | ------------------------------------------- |
| Could not authenticate | ユーザー名かアプリパスワードが間違っている  |
| SMTP connect() failed  | ホスト・ポート・暗号化の組み合わせが違う    |
| 文字化けする           | `CharSet = 'UTF-8'` が指定されていない      |
| `.env` の値が空になる  | 値に空白や `#` が含まれている（`"` で囲む） |

---

特に押さえておきたいのは次の3点です。

1. PHP は Gmail にメールを**預ける**だけで、ポートは 587 と tls の組み合わせを使う。
2. パスワードは `.env` に分けて Git に入れない。
3. PHPMailer は「設定して `send()`、失敗は `catch`」で書く。
